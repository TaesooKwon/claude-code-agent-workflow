## 위임·도구 경제
- **서브에이전트 1개 = 최소 ~40k 토큰.** 위임·스킬 오버헤드가 난이도로 정당화될 때만. 판단 = "인라인이면 몇 콜인가"가 소수면 위임이 손해. [[delegation-token-economy]]
  - **동일·기계적 편집 N개 = 팬아웃 금지**(인라인 `grep`+`Edit`, 많으면 에이전트 1개 일괄). 팬아웃은 대상마다 판단이 갈리는 작업(리뷰·조사·설계·검증)만. **한 줄 변경에 무거운 스킬 호출 지양**(파일 직접 Read+Edit).
  - **커밋으로 한 덩어리가 종결되면 다음 큰 작업은 새 세션 권장** 한 줄을 완료 보고에 붙이고, 무관 주제 전환엔 `/clear` 권유(사용량 70% 가 150k+ 컨텍스트에서 발생).
  - **병렬 실행 3축(순서 강제):** ①인라인 → ②결과만 결정적으로 받는 팬아웃 = **Workflow**(팬아웃 1순위) → ③실시간 지시 변경이 필요할 때만 **대화형 팀**(named, SendMessage 왕복). 한 건 위임 후 결과 회수 = background 서브에이전트이며 **`name:` 금지**(이름을 주면 팀메이트가 되어 유휴로 남고 보고가 유실된다). 3축은 새 기본값이 아니다. 팀을 고를 땐 그 agent type 이 `SendMessage` 를 보유했는지 스폰 전 확인.
  - **위임/워크플로우 프롬프트엔 하한선 5항목 라벨째 전사:** ①트러스트 경계 입력검증 ②데이터손실 방지 에러처리(경합 포함) ③보안(인가·시크릿·운영가드) ④접근성 ⑤명시요청 기능 — 무의미한 항목은 "N/A" 명시(침묵 누락 금지). 의도적 코너컷은 `// ponytail:` 표기 지시. [[delegation-prompt-transcribe-floor]]

## 편집 안전
- **최소주의 래더(포니테일 — 하한선 5항목의 본문):** 문제를 끝까지 읽은 **뒤** ①존재할 필요가 있나(YAGNI) → ②이 코드베이스에 이미 있나(재사용) → ③표준 라이브러리·플랫폼 네이티브(`<input type=date>`·CSS·DB 제약)·기존 의존성 → ④한 줄 → ⑤그제서야 최소 코드. 첫 성립 단에서 멈춘다. [[ponytail-ladder]]
  - 구현 1개짜리 인터페이스·팩토리·불변값 설정·"나중용" 스캐폴딩 금지, 추가보다 삭제, 최단 diff. 자른 코너는 `// ponytail: <한계> / <업그레이드 경로>`(장부 = 프로젝트 `ponytail-debt.sh`). 하한선 5항목(위 위임 절)은 래더가 절대 못 자른다.
  - 과잉설계 리뷰 관점은 커밋 워크플로에 상시 추가하지 않는다(토큰) — 의심 커밋에서만 빌트인 `/simplify`.
- **쓰기 전에 신규인지 확인하라(Write 는 통째로 갈아엎는다):** `git cat-file -e HEAD:<경로>`·`ls` 1콜로 부재 확인, 있으면 `Edit`. 도구 결과 `File created` = 신규 / `has been updated` = 덮어쓰기 — 신규인 줄 알았는데 updated 면 멈추고 `git show HEAD:<파일>` 로 원본 확인. **테스트 파일 특히 위험** — 성격이 다른 검증은 별도 테스트 클래스로. 커버리지 소실은 빌드·테스트가 초록이라 못 잡는다(staged diff 의 `@Test` 개수 증감을 본다). [[write-overwrites-existing-file]]
- **코드를 걷거나 더하면 그 코드를 서술하는 문장도 같은 편집 단위다(주석 드리프트):** 분기·컬럼·가드·API·산식 삭제·치환·**신설** 시 주석·JavaDoc·규약 문장을 같은 diff 에서 고친다. 판정 = "이 편집으로 거짓이 된 문장이 남는가". **정정문 자체를 재검증**하고, 옛 사실을 서술하는 층(스킬·규약·프롬프트·문서)까지 훑는다. [[comment-drift-same-edit-unit]]
  - ⚠️**더한 쪽이 훨씬 잘 빠진다**(삭제는 컴파일이 돕지만 추가는 아무도 안 돕는다) — 소비처·적재처·분기를 늘렸으면 그 개수·목록을 서술한 문장을 함께 고친다. **주석이 코드 밖 사실**(실행 순서·호출처 수·다른 파일 동작)**을 단언하려면 근거 명령 1개를 치고, 못 치면 역할로 서술한다.** [[comment-drift-same-edit-unit]]
  - **코드를 복제할 때 주석은 복제하지 마라** — 본문이 같아도 "왜 이 자리에 필요한가"는 자리마다 다르다(원본에서만 참인 문장이 복제본에서 거짓이 된다). **정정문 자체가 또 거짓인 사고가 반복된다** — 고칠 때도 명사를 grep 하고 같은 diff 의 테스트가 반증하지 않는지 본다. [[comment-asserts-facts-outside-the-code]]
  - **주석에 개수를 쓰지 마라**("N곳·N개·~뿐") — 구문이 하나 늘면 조용히 거짓이 되고 아무 층도 검사하지 않는다. 개수 대신 **①불변식(무엇이 보장되나) ②모집단 조회 명령**을 적는다. 세야 한다면 **소스 형태로 앵커**해 센다(`^\s*,COLUMN =`) — 앵커 없이 세면 **자기가 방금 쓴 주석·문서가 모집단에 섞인다**(2026-09-08 실측: 같은 문장의 개수를 3연속 틀렸고 마지막은 grep 을 치고도 났다).
- **1,000줄 넘는 파일은 줄을 더하기 전에 분해를 먼저 검토한다:** 판정은 diff 크기가 아니라 **파일 총 라인**이다(큰 파일일수록 리뷰 누락·복제 드리프트가 함께 자란다). 분해가 이번 범위를 넘으면 사유를 적고 진행하되 **사용자에게 말한다**(침묵 통과 금지).
  - **같은 파일이 두 모듈에 복제돼 있으면 한쪽만 고치지 마라** — 편집 전 양쪽을 실측하고, 한쪽만 고칠 거면 그 판단을 명시한다. 레포별 대형·복제 파일 목록은 프로젝트 memory.

## 상태주장·일반화·전제
- **상태주장은 검증 후 서술:** 현재 상태 주장이 권고·편집의 근거가 되면 서술 전에 반증할 가장 싼 명령 1개를 친다. 못 치면 "미검증(가정)" 라벨. 발동 = ①현재 상태 ②≤1~2콜 확인 가능 ③권고가 그 위에 얹힘(셋 다). [[verify-state-claims-before-asserting]]
  - **인계 큐를 복사·보고하기 전에 값싼 항목(줄번호·경로·수치)은 재측정해 치환한다** — stale 라인은 복사되며 사실로 굳는다. [[stale-carryover-queue]]
  - **grep 결과를 근거로 쓸 때의 6판정** — grep 은 존재 증명에 강하고 부재 증명에 약하다: ①**0 은 분모(모집단) 먼저**(분모 0 = "해당 없음") ②**양성 대조**로 패턴이 살아 있음을 확인 ③벤더·백업·산출물 트리 제외 + hit 소유 경로 확인 ④**`head`/`tail` 없이 `grep -c`·`wc -l` 로 다시 센다** ⑤**명령 실패와 결과 0 을 구분**(zsh 미인용 글롭은 명령을 통째로 죽인다 — 글롭·변수는 항상 인용, exit code 를 본다) ⑥"전수"는 개수가 아니라 **경계**(트리·확장자·변경종류 D/M/A/R·소유 축)를 먼저 적는다. 부재 주장은 grep 한 축으로 끝내지 말고 Read·LSP·교차표로 교차. [[population-boundary-before-exhaustive-claim]]
- **일반화는 표본 수와 함께 — 표본 1로 규칙을 만들지 마라:** "X만"·"전수"·"항상"·수치를 쓸 때 몇 개를 봤는지 적고, 표본 1이면 "표본 1 — 미검증 일반화" 라벨. "전수"는 파일 수가 아니라 파일 안의 요소 수. 환경 의존 수치는 조건을 붙인다("1440px 창 기준"). 관측 하나가 두 원인과 맞으면 판별축을 더 잰다. 주석·문서에 배타 단언("X만"·"유일한") 금지. 사용자가 "왜 이렇게 했냐"고 물으면 방어하지 말고 근거를 재측정. [[sample-size-and-premise-errors]]
- **설계 결정은 시나리오로 되읽어 컨펌받은 뒤 박는다(사양 되읽기):** 사용자 결정(D 목록)이 확정되면 결정마다 Given/When/Then 1~3줄로 되읽어 컨펌받고 설계서 "§시나리오(컨펌본)"에 둔다. 설계서와 코드가 **일치하는** 오해는 리뷰·테스트·E2E 가 못 잡는다. 결정이 경계·경로를 품을 때 특히 — "A 경로로 들어와도 X 가 있다"로 적는다. [[spec-readback-scenarios]]
- **팬아웃 전에 계약을 먼저 검증받아라:** 워크플로/서브에이전트 계약에 규칙·판정축을 박기 전에 에이전트 1개로 전제가 정본(가이드·표준 원문·공유 자산 실물·형제 레포)과 맞는지만 확인한다. 틀린 전제는 실행자와 검증자가 함께 밟아 사후 리뷰로 못 잡는다. 리뷰/verify 계약의 첫 항목에 "전제 반증"을 넣어라. [[sample-size-and-premise-errors]]
- **실수가 이어지면 개별 수리로 끝내지 말고 생성기를 찾아 규약화하라**(사용자 상시 지시 2026-08-07). 발동 = 같은 세션·주에 사용자 정정 2~3회 누적, 또는 사용자가 결함을 먼저 잡는 일이 반복. 절차 = ①그 세션의 실수를 이력에서 전수 나열(형태를 본다) ②공통 생성기 하나 ③기존 검증이 왜 못 잡았나(검사하지 않는 층) ④규약·훅·게이트·계약 필수항목으로 승격(배치 3규칙대로) ⑤진단·해결책·반영 위치 보고 후 승인. **방어하지 마라.**

## 비동기·검증
- **비동기 화면의 3대 재발 결함**(`$.ajax`·`fetch` 동일 — 정적검사·단위테스트로 안 잡힌다): [[async-wrapper-contract]]
  - ①**재진입 가드** `let loading=false` + 성공·실패 양쪽 해제. **제출·생성·삭제 = 드롭 / 조회성 재렌더 = last-wins**(시퀀스 토큰으로 낡은 응답만 폐기 — 조회성에 드롭을 쓰면 최종 선택이 유실). 안내 문구는 응답 시점이 아니라 요청 시점 값을 캡처. [[inflight-guard-drop-vs-lastwins]]
  - ②**공통 래퍼의 실패 계약을 착수 전 실물로 판정**: ⓐ실패 sentinel(`false`)을 콜백에 넘김 → 성공 콜백 선두 가드 ⓑ실패 시 콜백 미호출 → 잠금 해제는 콜백 밖 ⓒ래퍼 없음. 계약은 레이어(FO/BO)마다 다르고 팀 커밋 한 방에 바뀐다.
  - ③**라이브 리전 재낭독**: `role="status"` 는 값이 같아도 재대입되면 통지 → `if(el.textContent !== String(v))` 로 바뀔 때만. 비동기 검색의 0건·실패 박스엔 `role="status"`.
- **다층 관통 기능은 코드를 쓰기 전에 얇은 실물 왕복 1회부터(워킹 스켈레톤):** 입력에서 최종 소비(브라우저 렌더)까지 **서로 다른 프로세스·파일이 3개 이상** 끼면, 층마다 코드를 읽어 "되겠지"로 넘기지 말고 **가장 얇은 경로 하나를 끝까지 실행해 통과시킨 뒤** 살을 붙인다. 목·lint·컴파일·단위테스트가 **원리적으로 못 보는 조합**이라, 안 하면 한 층을 고칠 때마다 다음 층이 새로 막혀 수리가 연쇄한다(실측: 한 기능에서 결함 3개가 층마다 순차 발견 — 왕복 1회면 동시에 드러났다). [[walking-skeleton-before-layers]]
- **입력 방어는 금지 목록이 아니라 허용 목록으로 쓴다:** 막을 것을 열거하는 수리는 변형이 계속 나온다(실측: 한 방어에 백슬래시·공백문자·`%2e` 등 6종 우회). **허용할 형태를 정확히 적고** 나머지는 기존 방어에 맡긴다. 금지 목록을 늘리는 수리가 **2회째면 설계를 뒤집는다**(그 자체가 발산 신호). [[allowlist-not-denylist]]
- **로직엔 단위테스트 기본:** 분기·계산·필터·상태전이·배선엔 기본으로 붙인다. 제외 = 단순 위임/CRUD 패스스루, 외부의존 경계(DB·네트워크·파일·렌더 → 통합/E2E). 도구는 프로젝트 규약이 지정.
  - **경합이 있는 기능은 두 컨텍스트 동시 조작 E2E 가 필수**(폴링·동시 저장·상태전이·채번·커서): 동시 전송·교차 갱신 시나리오를 넣는다. 리뷰·단위테스트는 단일 흐름만 본다(리뷰 3회가 놓친 커서 결함을 E2E 1회가 잡았다). 절차 = `playwright-verify` 5-3절.
- **검증의 무게는 diff 의 성격에 비례(리스크 티어링 — 크기가 아니라 성격):** [[review-alite-dedup]]
  - **A티어(워크플로 리뷰) = 실행 의미가 바뀌는 변경**(서버 코드·DB 접근·인증/인가·상태 전이·비동기/이벤트 배선·조건 분기 신설). **B티어(셀프리뷰) = 표현만**(마크업·문구·스타일, 바인딩·분기·핸들러 무변경). 판정은 기계적 축(①로직 소스 ②쿼리·매퍼 ③인라인 스크립트 동작 ④조건·반복 바인딩 신설 중 하나라도 → A). 확장자 축은 프로젝트 규약.
  - **소형 A = 단일 에이전트 델타형 리뷰(A-라이트 폐지 2026-09-03):** ⓐ≤5파일 ⓑ인증/인가·상태전이·비동기 배선·신규 스키마 무변경 ⓒ로직 단위테스트 커버 — 셋 다면 에이전트 1개(세션 모델)에 behavior+regression 을 한 프롬프트로 주고 **CONFIRMED 제목·파일·라인 1:1 수리 체크리스트**로 받는다. 하나라도 미충족이면 풀 A. 경량 실행 사실을 보고.
  - **verify 는 지적을 병합해 고유당 1회 판정, 실행은 파일 단위 배치.** 병합 키는 `(file, 라인)` 정확일치가 아니라 라인 근접·제목 유사(서로 다른 관점 사이만). 배치는 에이전트 1개 사망이 그 파일 지적 전부를 삼키므로 **미판정은 기각이 아니라 게이트 차단**. **verify 모델 하향·델타 재리뷰 생략 금지.**
  - **강등 조건 4가지:** ⓐ애매하면 A ⓑB 도 빌드·렌더 검증은 그대로 ⓒB 판정을 사용자에게 말한다(침묵 강등 금지) ⓓ마커·지문 대조는 티어 무관.
  - **검증은 병렬**(렌더/E2E 와 리뷰는 읽기전용 — 동시에). 같은 세션에서 확인한 화면은 재검증 안 함. **리뷰 위임 스키마에 "그 지적이 걸리는 변경 라인" 필수 필드**(스코프 밖 지적을 구조적으로 차단).
  - **수리 → `git add` → 델타 재리뷰 → 빌드·검증 → 마커 → 커밋.** 재스테이징을 빼먹으면 리뷰 전 코드가 커밋된다(마커 지문은 인덱스 기준).
  - **병행 세션과 인덱스를 공유할 땐** ①일괄 스테이징 금지(`git add -A/--all/-u/.`·`commit -a` — 훅 `git-add-all-guard.sh`) ②리뷰는 내 변경만 복사한 worktree 에서 선실행(`args.repo`), 상대 커밋이 HEAD 에 든 뒤 메인에서 재스테이징 → `git diff --cached | grep -v '^@@'` 대조 → 마커 → 커밋. [[parallel-session-shared-index]]
  - **델타 재리뷰 = 새 단일 에이전트 1개에 1차 지적·수리 주장·수리 diff 를 전사**(워크플로 에이전트는 주소가 없어 `SendMessage` 불가). "수리가 절반인가·새 결함을 만들었나·기각 지적 재상정 금지" 지시. 템플릿 = 프로젝트 `.claude/workflows/delta-review.md`.
- **전체 E2E 회귀 스위트 = 온디맨드(커밋 게이트 금지):** 전량 실행은 사용자 요청 시. 커밋 상비 게이트 = 빌드·단위테스트·자체 리뷰까지. 무거운 축(설정·인증/세션·DB 스키마·공통 모듈) 커밋 땐 전량 회귀를 **제안**. 관련 spec 서브셋은 재량.
- **테스트는 "통과"가 아니라 "실패할 수 있음"을 확인하라(반증검사):** 새·수정 단언은 기대값을 고의로 어긋나게 해 빨간불 1회 확인. 방어적 `if(있으면 확인) else 로그` 는 영원히 통과. ①셀렉터·경로는 실물 확정 ②응답 계약(메서드·status·코드)까지 단언 ③저장값 재조회 ④필터는 양성+음성 ⑤정리는 teardown 훅에.
  - **부칙 — 반증검사 자체가 거짓을 말할 수 있다**("빨간불 안 뜸" = 거짓 초록 또는 미실행): ⓐ**변이 적용 건수를 `assert`**(비가시 문자는 이스케이프로) ⓑ메시지 단언은 전문 일치·구조적(부분문자열이 다른 실패 경로에 걸린다) ⓒ몇 건이 왜 깨져야 하는지 먼저 적고 대조 ⓓ**`Tests run: N>0` 단언** — 컴파일 실패·미실행은 "미반증"이지 통과가 아니다(변이는 컴파일되는 형태로).
  - **⑥결함이 특정 층에만 살면 검증도 그 층에서**: 목 테스트는 아래 층(매퍼 SQL 텍스트·ORM 쿼리·생성 산출물)을 원리적으로 못 본다 → 렌더된 SQL 문자열을 단언. lint 는 문법을 볼 뿐 값의 자리는 안 본다.
