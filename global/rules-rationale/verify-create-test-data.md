화면·분기 검증에 필요한 데이터가 개발 DB에 없으면, 확인 불가로 보고하지 말고 테스트 데이터를 만들어 확인한다. 로컬 개발 테스트는 개발 DB 또는 로컬 DB 를 쓰므로 테스트 데이터 생성은 문제가 되지 않는다.

**Why:** 한 레포에서 화면 분기 2건을 "개발 데이터에 해당 행 없음 → 확인불가"로 보류했다가, 사용자가 "데이터를 만들어 확인하라"고 지시하고 상시 규칙으로 올렸다(2026-10-23). 보류된 분기는 결국 아무도 확인하지 않은 채 남는다 — "데이터 생기면"은 오지 않는다.

**How to apply:**
- 생성 순서 = ①화면 경유(ID 채번·감사 컬럼이 실경로를 탄다) → ②안 되면 개발 DB 직접 쓰기.
- 기존 테스트 행을 잠깐 바꾸는 것도 된다(예: 수업을 모집 종료 학기로 옮기기, 첨부 컬럼 NULL). 순서 = 원값 SELECT 로 기록 → 원값을 조건에 건 UPDATE → 확인 → 역 UPDATE → SELECT 로 원값 대조.
- 새로 만든 행은 식별 가능한 이름(예: `[E2E<MMDD>] …`)으로 만들고 끝나면 소프트삭제한다.
- 운영 DB 는 절대 대상이 아니다.
- 레포별 예외(예: 학생·교사 계정은 포털 픽스처 경로로만, 공유 행 변경은 원값 기록 책임을 지는 세션만)는 프로젝트 규약이 가진다.
- 위임 결과에 "데이터 없음"이 오면 그것을 결과로 보고하지 말고 메인이 데이터를 만들어 재확인을 맡긴다.
