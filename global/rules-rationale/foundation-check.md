## 규칙
첫 화면 착수 전(또는 인계 초기소스·팀 공통 모듈 유입 직후) `foundation-check` 스킬을 돌리고, 결함은 화면이 아니라 기반에서 고친다.

- 독립 반증(확인 8 / 반증 8 / 미확인 4)이 정정한 것:
  - "기반 한 곳 수리로 끝났다"는 **틀렸다** — 대표 27건 중 기반 1곳 8 / 혼합 6 / 화면·도메인형 13, fix 비테스트 파일 중앙값 4. 가치는 "처음 정할 때 확산 방지"이고 "기반이 있었다면 막혔다"는 git 으로 입증 불가한 반사실이다.

  - JSP 레포는 raw `$.ajax` 수백 회·전역 핸들러 0 → 레버는 공통 래퍼가 아니라 전역 `ajaxError`/`ajaxSetup`.

- 같은 계열의 기존 조항(비동기 재진입 가드·공통 래퍼 실패 계약)이 전역에 있었는데도 화면 누락이 나왔다 — 코드 쓸 때 떠올려야 하는 규칙보다 **정해진 시점의 관문**이 덜 샌다는 판단이 이 스킬의 형태(체크리스트 1회 실행)를 정했다.
