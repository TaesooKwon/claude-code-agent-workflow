전역 조항 **"일반화는 표본 수와 함께"** · **"팬아웃 전에 계약을 먼저 검증받아라"** 의 근거. 규칙 문장은 `~/.claude/CLAUDE.md` 에 있다.

## 실측 근거 — 2026-08-07 하루, 실수 6건이 전부 같은 형태였다

전부 **표본 1개를 규칙으로 승격**한 형태다:

1. 포커스 누락 1건을 보고 **"X만 누락"** — 같은 구조 컴포넌트가 2종 더 있었다.
2. 파일 12개를 세고 **"전수 적용"** — 파일당 해당 요소가 2개인 케이스를 놓쳤다.
3. **1440px 창에서 잰 값**을 폭 상수로 승격 — 실제로는 창 크기 비례값이었다.
4. "실사용 0건"에서 **"버렸다"로 원인 단정** — 실제는 아키텍처가 달라 못 쓰는 것이었다.
5. 가이드의 **3분기 선택을 일괄 규칙으로 뭉갬**.
6. 기존 코드 1건을 **"전례"로 승격** — 사용자 답변은 "그냥 기본 틀".

파생 교훈:
- **환경 의존 수치는 조건을 붙여 말한다** — "1,056px"이 아니라 "1440px 창 기준 1,056px". 이 하나로 형제 레포 판정과 내 레포 판정이 **둘 다** 틀렸다.
- **관측 하나가 두 원인과 맞아떨어지면 한 축을 더 잰다** — "실사용 0건"은 "버렸다"에도 "구조상 못 쓴다"에도 맞는다. 그때의 판별축은 컨트롤러의 model 주입 여부였다.
- **배타 단언을 주석에 쓰지 마라** — 실제로 리뷰어가 내 주석을 "사실오류"로 지적했다.
- **사용자가 "왜 이렇게 했냐"고 물으면 그 자체가 신호다** — 그 질문으로 드러난 오류가 그날 **4건**이었다.

## 전제 오류가 리뷰의 구조적 사각인 이유

같은 날, 리뷰는 **잘 작동했다** — 지적 8건 전건 CONFIRMED, 렌더 검증이 심각 결함을 적발했다. 그런데 **전제 오류만 못 잡았다.** 틀린 전제는 실행자와 검증자가 **함께 밟기** 때문이다.

**비용 비대칭 실측**: 계약 한 줄이 틀려 **13화면 오적용 → 6화면 되돌림**. 선검증 에이전트 1개 vs 재작업 N개면 비교가 안 된다.

**How to apply:** 리뷰/verify 계약의 **첫 항목에 "전제 반증"** 을 넣는다(기존 프롬프트 구조 그대로 한 항목 추가). 팬아웃 전에는 에이전트 1개로 "이 계약이 전제한 규칙들이 맞는지만 검증하라, 작업은 하지 마라".

## 경위(2026-09-17 이동)

**상태주장:4 축약(원문 잔여):** "'X만'·'전수'·'항상'·수치를 쓸 때 몇 개를 봤는지 적고, 표본 1이면 '표본 1 — 미검증 일반화' 라벨. **'전수'는 파일 수가 아니라 파일 안의 요소 수.** 환경 의존 수치는 조건을 붙인다('1440px 창 기준'). **관측 하나가 두 원인과 맞으면 판별축을 더 잰다.** 주석·문서에 배타 단언('X만'·'유일한') 금지. 사용자가 '왜 이렇게 했냐'고 물으면 방어하지 말고 근거를 재측정."

**상태주장:6 축약(원문 잔여):** "워크플로/서브에이전트 계약에 규칙·판정축을 박기 전에 에이전트 1개로 전제가 정본(가이드·표준 원문·공유 자산 실물·형제 레포)과 맞는지만 확인한다. 틀린 전제는 실행자와 검증자가 함께 밟아 **사후 리뷰로 못 잡는다**. 리뷰/verify 계약의 첫 항목에 '전제 반증'을 넣어라." — 이 항목은 프로젝트 `.claude/workflows/commit-review.js` 의 verify 프롬프트에 이미 배선돼 있다(2026-09-17 처분표 실측 주장, 라인 인용은 stale 위험이라 생략).

## 출처 태그 조항(2026-10-02 추가)
**경위:** 예시 레포의 세션 트리오(설계·구현·검증 세션 분담)에서 사용자가 「한번더 검토」를 요구한 뒤 설계가 4건 바뀌었다 — 반증 요청에는 설계 세션이 "전제"라고 의식한 코드 사실 4건만 넣었고, 인계 memory 에서 옮긴 문장(폴링이 401 에서 즉시 정지한다 — 두 앱 중 한쪽만 참)과 자기 가정은 검증 목록 밖이었다. 같은 형태 3회째. 기존 규칙("반증 목록엔 근거·이유 문장도 넣는다")은 트리오 착수 때만 읽는 memory 에 있어 적용되지 않았다 → 전역 조항으로 승격.
**판정:** 태그는 자기 적용이라 오류를 만든 세션이 스스로 붙인다는 한계가 있다 → 아래 보충.
**보충(같은 날 사용자 승인):** ①독립 반증 — 태그 붙은 설계 전문을 설계를 쓰지 않은 검증자 1개가 반증하고, 제시 머리에 "확인 n / 반증 m" ②변경 공개 — 이미 제시한 설계를 고치면 바뀐 것·원인 분류·출처 표. 사용자 문제 제기 = "설계1 과 설계2 가 많이 바뀌면 신뢰할 수 없다". ③훅(최종 답의 시나리오·컨펌 요청 + 잔존 [인계]/[가정] 경고)은 키워드 오탐 위험으로 보류 — ①②뒤 재발 시 승격.
**일반화:** 사용자 "트리오 작업이 아닐때도 적용될 수 있게" → 조항 문구에서 트리오 용어를 걷고 `[조사]` 태그·"유휴 피어 세션, 없으면 background 서브에이전트"로 바꿨다. 적용 범위 = 사용자 컨펌을 받는 설계·시나리오(컨펌 절차가 없는 한 줄 수정은 대상 아님 — 서브에이전트 1개 ~40k 비용).
