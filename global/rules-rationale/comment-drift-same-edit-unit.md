# 주석 드리프트 — 실측 3회와 승격 경위

전역 `CLAUDE.md` 조항 **"코드를 걷거나 더하면 그 코드를 서술하는 문장도 같은 편집 단위다"**의 근거.

## 실측 3건 (예시 레포, 2026-08-19 — 전부 한 세션 안에서)

| # | 무엇을 걷었나 | 남은 거짓 문장 | 성격 |
|---|---|---|---|
| ⓐ | 수강신청 URL 을 GET 화이트리스트에서 철회 | "GET 화이트리스트에 있고…" 주석 잔존 | 삭제분을 서술하는 주석 |
| ⓑ | ⓐ를 정정하며 새로 쓴 문장 | "인증만으로 열린다" — **실제로는 메뉴 인가도 받는다** | **정정문이 다시 부정확** |
| ⓒ | 그리드 '권한' 컬럼 삭제 | 폭 예산 주석이 **옛 산식** 그대로 | 수치·산식 주석 |

세 건 다 **커밋 전 리뷰가 CONFIRMED 로 잡아 유출은 없었다.** 즉 문제는 유출이 아니라
**매번 리뷰 왕복 비용을 태운다는 것**이고, 예방층(작성 시점)이 비어 있었다는 것이다.

## 왜 리뷰가 아니라 규약으로 승격했나

- 리뷰 계약에는 이미 항목이 있다 — `.claude/workflows/commit-review.js` 의 `regression` 관점 6번
  ("변경된/남겨진 **주석이 새 동작과 모순**되지 않는가? 주석의 배타 단언도 확인하라").
  그리고 그 항목이 실제로 3건을 전부 잡았다. **검증층은 정상 작동 중이라 손댈 곳이 없었다.**
- 훅은 부적합하다 — 주석의 참·거짓은 기계 판정이 불가능하다(문자열 매칭으로는 "옛 사실"을 못 센다).
- 남은 빈 층은 **작성 시점 예방** 하나뿐이라 선언(규약)이 정확히 맞는 사다리 칸이었다.
  사다리 = 경험(history) → 교훈(memory) → 절차(skill) → 강제(hook); 여기서는 memory 마킹 2회를
  거쳐 3회째에 규약으로 올렸다(`promotion-candidates` 대기열 운용의 첫 실사용 사례).

## 판정축

- **"이 편집으로 거짓이 된 문장이 파일에 남는가"** — 이것만 물으면 된다. 주석을 전수로 읽는 게 아니라
  **내가 방금 걷어낸 것**을 서술하는 문장만 찾으면 된다(대개 같은 파일·같은 메서드 안).
- 잘 썩는 것 = **수치·산식 주석**(ⓒ), **배타 단언**("X만"·"유일한" — 전역 일반화 조항의 짝),
  존재하지 않는 함수·경로를 가리키는 서술(예시 레포 실측: `js/cms/app.js:917-919` 가 존재하지 않는
  서버 검증 `validateFileExtensions` 를 설명하고 있었다 — 코드가 아니라 **처음부터 없던 것**을 서술).
- **정정문도 재검증한다**(ⓑ). 한 축만 보고 고치면 같은 자리에서 두 번 틀린다 —
  [[verify-state-claims-before-asserting]] 와 같은 축이다.
- 층은 코드 주석만이 아니다 — **스킬 `SKILL.md`·규약 md·위임 프롬프트·설계 문서**까지.
  전역 "정책을 개정하면 복제된 모든 레이어를 grep" 조항과 같은 축이고, 그쪽이 **정책 문구**를
  다룬다면 이 조항은 **사실 서술**을 다룬다.

**Why:** 세 건이 서로 달라 보였지만 생성기는 하나였다 — "편집 단위를 코드까지로만 봤다".
리뷰가 잡아주니 손해가 안 보였지만, 실제로는 매 커밋마다 리뷰 왕복이라는 고정비를 태우고 있었다.

**How to apply:** 코드를 삭제·치환한 직후, 그 자리 주변에서 **방금 걷어낸 것을 설명하는 문장**을
같은 diff 안에서 고친다. 고쳐 쓴 문장은 다시 한 번 반증한다. 관련 = [[sample-size-and-premise-errors]]
(배타 단언) · [[verify-state-claims-before-asserting]] (정정문 재검증).

## 개정 2026-09-04 — "걷으면"에 "더하면"을 더했다 (표본 3커밋·5문장, 한 세션)

초판은 **삭제·치환**만 편집 단위로 봤다. 그 뒤 한 세션에서 같은 형태가 3커밋 연속으로 리뷰에 잡혔는데,
가장 많이 빠진 유형이 **추가**였다.

| 사례 | 쓴 문장 | 실제 |
|---|---|---|
| eGov AOP | "ERROR 스택을 쌓지 않는다" | `AopExceptionTransfer` 가 ERROR 한 줄을 먼저 남긴다 |
| 픽스처 주석 | "두 줄이 빠지면 전부 거부된다" | 폴백이 있어 통과 — **같은 diff 의 자기 테스트가 반증** |
| 모달 스태킹 | "팝업 스크립트보다 **뒤**에 두어 알럿이 **위**에 뜬다" | **정반대**. classic 은 파싱 중 즉시, module 은 항상 defer |
| 적재처 | "레이아웃 어드바이스가 적재" | **같은 커밋이** 두 번째 적재처를 만들었다 |
| 계수 | "소비처가 셋이다" | 실호출처와 불일치 |

### 생성기

**주석이 "코드 밖 사실"을 단언할 때만 틀렸다.** 코드 바로 옆 사실(이 분기가 무엇을 하는가)은 하나도
안 틀렸다. 틀린 것은 전부 셋 중 하나다:

1. **실행 순서** — 다른 파일·다른 스크립트 타입이 언제 도는가(classic vs module, AOP 개입, 필터 순서)
2. **호출처·소비처의 개수나 목록** — "셋이다", "여기 하나뿐이다"
3. **같은 diff 가 방금 더한 사실** — 적재처를 하나 더 만들어 놓고 옛 문장을 그대로 뒀다

③이 가장 잘 빠진다. **내가 만든 변화라 안다고 착각하고 그 문장을 다시 읽지 않는다.**
구조적 이유도 있다 — **삭제는 컴파일러가 돕는다**(사라진 심볼을 참조하면 빌드가 깨진다).
**추가는 아무도 안 돕는다**: 옛 문장은 문법적으로 멀쩡하고, 그저 거짓이 될 뿐이다.

### 판정축 추가

- 소비처·적재처·분기를 **늘렸으면** 그 개수·목록을 서술한 문장을 함께 고친다.
- 주석에 **코드 밖 사실**을 쓰려면 그 자리에서 **근거 명령 1개**를 친다(실행 순서 → 실측 하네스·`javap -c`,
  개수 → `grep -c` + 경계 명시). 못 치면 단언하지 말고 **역할 축**으로 서술한다
  ("소비처가 셋이다" → "적재 = A·B / 소비 = C / 검증 = 목적지를 정하는 모든 지점").

### 왜 이번엔 검증층도 함께 손댔나

초판 개정 때는 "리뷰 `regression` 6번이 이미 잡고 있어 검증층은 손대지 않았다"고 적었다. 그 판단은
여전히 옳다 — 이번에도 리뷰가 5건을 전부 잡았다. 다만 **3연속으로 잡혔다는 것은 작성 시점 예방이
안 먹고 있다는 뜻**이라, 이번에는 ⓐ작성 시점(이 조항)과 ⓑ검증 시점(`regression` 6번에 "이 diff 가
더한 것" · "코드 밖 사실 단언" 축 추가)을 **둘 다** 보강했다. ⓐ가 본체이고 ⓑ는 새는 것을 받는 그물이다.

⚠️ 미사용 import 도 같은 사각지대다 — 예시 레포 컨벤션 lint 룰셋(A~H)에 미사용 import 검사가 없어
승격·이동 후 죽은 import 가 컴파일·테스트·하네스를 전부 통과했다.


## 경위(2026-09-17 이동)

**편집안전:5 축약(원문 잔여):** "분기·컬럼·가드·API·산식 삭제·치환·**신설** 시 주석·JavaDoc·규약 문장을 같은 diff 에서 고친다. **정정문 자체를 재검증**하고, 옛 사실을 서술하는 층(스킬·규약·프롬프트·문서)까지 훑는다."

**편집안전:6 병합(원문 전문):** "⚠️**더한 쪽이 훨씬 잘 빠진다**(삭제는 컴파일이 돕지만 추가는 아무도 안 돕는다) — 소비처·적재처·분기를 늘렸으면 그 개수·목록을 서술한 문장을 함께 고친다. **주석이 코드 밖 사실**(실행 순서·호출처 수·다른 파일 동작)**을 단언하려면 근거 명령 1개를 치고, 못 치면 역할로 서술한다.**"

**편집안전:7 병합(원문 전문):** "**코드를 복제할 때 주석은 복제하지 마라** — 본문이 같아도 '왜 이 자리에 필요한가'는 자리마다 다르다(원본에서만 참인 문장이 복제본에서 거짓이 된다). **정정문 자체가 또 거짓인 사고가 반복된다** — 고칠 때도 명사를 grep 하고 같은 diff 의 테스트가 반증하지 않는지 본다."

**편집안전:8 축약(원문 잔여):** "주석에 개수를 쓰지 마라('N곳·N개·~뿐') — 구문이 하나 늘면 조용히 거짓이 되고 아무 층도 검사하지 않는다. 개수 대신 ①불변식(무엇이 보장되나) ②모집단 조회 명령을 적는다. 세야 한다면 **소스 형태로 앵커**해 센다(`^\s*,COLUMN =`) — 앵커 없이 세면 **자기가 방금 쓴 주석·문서가 모집단에 섞인다**(2026-09-08 실측: 같은 문장의 개수를 3연속 틀렸고 마지막은 grep 을 치고도 났다. 2026-09-07 한 커밋에서 3→1→2건)."

**기계화 한계:** 후보 목록 제시(프로젝트 `comment-selfcheck.sh`)까지만 — 판정형 lint 는 재현율 1/4·정밀도 0/3 으로 기각된 이력이 있다. 레포별 사례는 프로젝트 회상층(예시 레포 = `comment-asserts-facts-outside-the-code`).
