# 전역 규약 근거 저장소 (rules-rationale)

전역 `~/.claude/CLAUDE.md` 조항의 **경위·실측·사례**를 담는 단일정본. 자동 로드되지 않고, 조항의 `[[포인터]]`를 만났을 때 **필요하면 그때 읽는다**.

## 왜 프로젝트 memory 가 아닌가

회상층(memory)은 **프로젝트별**인데 전역 규약은 **모든 레포에 로드된다.** 전역 조항의 근거를 한 프로젝트 회상층에 두면 그 레포에서만 살아 있고 나머지는 전부 죽은 링크가 된다.

실측(전 레포 교차검사): 전역 포인터 5건이 작성된 1개 레포 외 **6개 레포 전부에서 미존재**였다. 복제안도 같은 검사에서 탈락했다 — 두 레포의 같은 근거 파일이 **이미 드리프트**해 있었다(2,209 vs 2,501B). 자세한 배경 = `METHOD.md` §9.6.

## 규칙

- **전역 조항의 근거 = 여기.** 프로젝트 회상층에 복제하지 않는다(드리프트 원인).
- **프로젝트 고유 교훈은 여기 두지 않는다** — 그건 해당 프로젝트 회상층 몫이다.
- 파일 형식은 회상층과 동일(frontmatter + `**Why:**` / `**How to apply:**`). `[[포인터]]`로 서로 링크한다.
- 프로젝트 회상층을 가리키는 링크는 **어느 레포 것인지 표기**한다(다른 레포에선 안 열린다).
- 회상층에서 이관한 자리에는 **인덱스 한 줄로 행선지를 남긴다**(다음 세션이 "사라졌다"고 오독하지 않게).
- 이 디렉터리는 상시 로드가 **아니므로** 크기 예산과 무관하다 — 서사를 여기로 밀어내는 것이 곧 예산 확보다.

## 새 머신에서

`bootstrap-machine.sh` 가 이 `README.md` 를 `~/.claude/rules-rationale/` 로 설치한다. 근거 파일 자체는 **머신마다 쌓이는 개인 자산**이라 킷에 담기지 않는다(회사·프로젝트 식별자가 섞이므로 반출 금지).
