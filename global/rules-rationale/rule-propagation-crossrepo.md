동일 스택 형제 레포(`형제레포1` = **규약 정본**)와 규약을 대조·전파할 때의 방법과, 예시 레포에서 확정된 격리 판정.

**2026-08-07 전파 3방향 완료:**
- **지역A → 예시 레포 (6건)**: 알럿/Toast UI 2종·공통유틸 승격·md 커밋제외·harness 룰 L·K 표기·3축 포인터.
- **예시 레포 → 지역A 역전파 (3건, 스택 공유)**: `App.requestFetch` 인증오류 `false` 계약·비동기 재진입(in-flight) 가드·
  라이브 리전 재낭독. 전부 WP2.1 리뷰 실적발.
  ⚠️**전파 시 내가 저지른 오류(사용자 지적으로 정정)**: "지역A FO 개발 JS에 가드 0건이라 같은 결함 노출 중"이라고
  단정했으나 실측 결과 **①지역A FO `js/front/` 엔 `requestFetch` 호출부가 아예 0건**(노출될 코드가 없음)이고
  **②실사용은 BO 204건**이며 **③BO `alert` 은 호출마다 `<dialog>` 를 새로 append·`showModal()` 해서
  두 개가 스택될 뿐 앞 메시지가 안 지워진다** — 예시 레포 FO 의 `pendingCancel` 싱글턴(정보 소실)과 **실패모드가 다르다**.
  ⇒ **`grep -c` 0건 하나로 상대 레포 상태를 단정하지 말 것** — 계약·구현·**호출부 존재**를 각각 확인해야 한다
  ("가드 0건"과 "호출부 0건"은 전혀 다른 사실인데 같은 0으로 보인다).
  ⚠️**2차 정정**: 그 뒤 "구현이 레포마다 다르다"고 다시 단정한 것도 틀렸다. 교차 실측(FO/BO × 2레포) 결과
  **지역A·예시 레포 가 FO 끼리, BO 끼리 동일**했다 — **갈리는 축은 레포가 아니라 FO/BO 레이어**다
  (FO=`pendingCancel` 싱글턴 4건·Promise / BO=둘 다 0, 호출마다 dialog 신규 append).
  ⇒ 한 번 틀린 뒤 **급히 내놓은 대체 설명도 같은 수준의 미검증 추측**이 되기 쉽다. 정정할 땐 원 주장보다 **더 넓게** 측정하라
  (한 축만 보지 말고 교차표를 만들어라). [[verify-state-claims-before-asserting]] 의 전형적 위반 2연속이었다.

## 부수 발견 — `app.js` 는 퍼블 자산이 아니라 우리 소유

퍼블 소유는 `js/design/**` 뿐이고 `app.js` 는 FO `kr/example/cms/comn/site/js/`·BO `js/cms/` 에 있는 **우리 경로**다.
같은 퍼블 `<dialog class="modal">` 마크업을 쓰되 **띄우는 래퍼를 BO/FO 가 따로 만들어 각자 진화**시킨 결과가 이 차이다.
⇒ 고쳐도 다음 퍼블 반입에 덮이지 않는다. 근본 개선안 = **싱글턴 유지 + 재진입을 덮어쓰기가 아니라 큐잉으로**
(정보 보존 + 스택 방지 동시 확보). 4파일 + 전 화면 회귀 규모라 별건 착수.
- **→ 전역 + 킷 (3건, 스택 불문 방법론)**: 수리분 재스테이징 절차·델타 재리뷰는 1차 에이전트에 `SendMessage`·
  본 문서의 대조 방법. 킷 커밋 `0b93682` (global/CLAUDE.md·agent-scaffold tmpl·METHOD.md).
  ⇒ **전역에 넣으면 7개 레포에 자동 적용**된다(레포별 복제 불필요). 방법론을 지역A(정본)에 쓰면 나머지 5개에 드리프트가 생긴다.
- **형제 5개 레포 조사 완료**(`형제레포3`·`형제레포6`·`형제레포4`·`형제레포5`·`형제레포2`):
  전부 **eGov Maven + JSP 단일모듈**(`src` 하나, Thymeleaf 아님)이고 **`app.js` 없음**,
  jQuery **`$.ajax` 직접 호출**(30~731건)에 **팀 래퍼 없음**. ⚠️`ajaxExtend`/`ajaxHandleResponse` 를
  래퍼 후보로 잡았던 grep 은 **jQuery 내부 함수 오탐**이었다. `형제레포3`·`형제레포6` 는 pom·파일수 동일 = 같은 프로젝트 두 체크아웃.
  ⇒ sentinel 가드 규칙은 **미해당**(전이할 래퍼가 없다), 재진입 가드·라이브 리전은 해당.
  ⇒ **5개 파일에 복제하지 않고 전역에 "비동기 화면의 3대 재발 결함" 조항으로 단일 기재**(킷 `0fd85ba`).
  7개 레포 동시 커버 + 드리프트 0 — 위 배치 3규칙①의 적용 사례.

**Why:** 사용자가 "전파하라 했는데 다 안 된 것 같다"며 스크린샷으로 누락(병렬 3축)을 직접 짚어냈다.
내가 쓴 대조 방법이 구조적으로 항목을 놓쳤기 때문이다.

**How to apply:**

## 대조는 앵커 차집합이 아니라 섹션별 전문 Read

bold 앵커(`- **...**`) 차집합은 **양방향으로 틀린다** — ①문구만 다른 동일 조항을 위양성으로 대량 배출
(관리자 체크박스·App.paging·모델 티어·이식 킷 등이 전부 "누락"으로 잡혔으나 실제론 있었다)
②**하위 들여쓰기 항목**(`  - **...**`)과 포인터형 조항을 놓친다(3축이 이렇게 샜다).
⇒ 형제 레포 md를 **섹션별로 Read** 한다. 내 프로젝트 md는 세션 시작 시 이미 컨텍스트에 있으므로
**상대 것만 읽으면 되어 비싸지 않다**(41KB ≈ 12k 토큰, 서브에이전트 위임보다 싸다).

## 배치 3규칙 (어디에 둘 것인가)

1. **스택 불문 방법론·판단원리** → 전역 `~/.claude/CLAUDE.md` 단일정본.
   프로젝트에는 `정본 = 전역` **포인터 + 이 레포 판정축**만 둔다.
   원리는 공통이어도 **판정축은 스택마다 다르다**(리스크 티어링 A/B 판정이 예시 레포는 `th:if`, JSP 레포는 `<c:if>`).
   전역에 몰면 못 쓰고, 프로젝트에만 두면 원리가 사라져 매번 재발명한다.
2. **동일 스택 공유 자산 규칙**(퍼블 컴포넌트·공통 유틸·팀 표준) → **각 프로젝트 md에 중복 기재**.
   `App.alert`·`window.toast` 같은 사내 자산은 전역감이 아니다(무관 프로젝트 오염).
   ⚠️런타임 자동 로드는 **전역 + 프로젝트 둘뿐**이라(`agent-scaffold`는 부트스트랩 1회 복사) **공유층을 새로 만들어도 안 읽힌다.**
   ⇒ 드리프트 해법은 층 추가가 아니라 **전파 확인 절차**다.
3. **도메인 표준값·접속정보·포트** → 프로젝트 격리(전역 반입 금지).

## 전파 시 시그니처·경로는 반드시 실물 확인

지역A 문구를 그대로 복사하면 안 된다 — 같은 이름의 API도 레포마다 계약이 다르다.
실측 예: 예시 레포 FO `App.confirm` 은 **Promise + 레거시 3인자 동시 지원**(지역A 문서엔 Promise만),
BO 는 콜백 `(id, msg, handler)`. 경로·존재 여부(ArchUnit·스냅샷)도 매번 확인한다.

## 전역 규약에서 이관된 실측 사례 (2026-08-10 C안)

전역 `~/.claude/CLAUDE.md` 의 「에이전트 플로우 전파」 항목에는 규칙 문장만 남기고, 그 근거인 아래 사례를 여기로 밀어냈다.

- **앵커 차집합의 위양성 규모**: "누락"으로 잡힌 **20여 건 중 절반이 이미 있던 조항**이었다(문구만 달랐다). 반대 방향의 누락은 **사용자가 스크린샷으로 직접 짚어냈다** — 즉 차집합은 위양성과 위음성을 동시에 낸다.
- **전문 Read 가 싼 이유**: 상대 레포 규약 40KB ≈ 12k 토큰. 서브에이전트 위임(최소 ~40k)보다 싸므로 "비싸서 차집합을 쓴다"는 정당화는 성립하지 않는다.
- **정책 개정 시 `SKILL.md` 가 구조적 사각이다**: 전량 E2E 회귀를 "커밋 게이트 → 온디맨드"로 전환할 때 규약 md·`settings.json` 훅 등록·전역·스캐폴드·이식 킷 5지점을 훑었는데 `.claude/skills/**/SKILL.md` 만 남아 `new-screen` 스킬이 "커밋 전 회귀"를 계속 지시했다. **같은 누락이 두 레포에서 독립적으로 재현**됐다(한쪽은 타 AI 지적, 다른 쪽은 그 후속 점검) — 우연이 아니라 구조적 사각이라는 증거다.
- **스캔 히트의 성격 오판 사례**: 타 AI 가 스킬 frontmatter `description:` 의 트리거 키워드를 "구 정책 잔존"으로 오독했다. 트리거 문구는 정책 서술이 아니라 존치 대상이다.
