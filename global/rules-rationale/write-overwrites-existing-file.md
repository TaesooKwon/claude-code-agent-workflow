전역 `~/.claude/CLAUDE.md` **"쓰기 전에 신규인지 확인하라"** 조항의 경위·실측. 규칙 문장은 그 조항에 있고 여기엔 근거만 둔다.

## 실측 사고 (2026-08-20, eGov/Maven 멀티모듈 레포)

SSO 복귀 지점 테스트를 **"신규 작성"한다고 생각하고** 어느 레이아웃 어드바이스의 테스트 클래스에 `Write` 했다.
그 파일은 이미 존재했고 **`@Test` 18건**을 담고 있었다. 7건으로 줄어든 채 스테이징까지 갔다.

날아간 것 중에는 인가 계약 회귀 게이트 4건이 있었다 —
"같은 요청에서 인가 조회를 1회만 한다", "요청이 다르면 다시 조회한다 = 권한 회수가 즉시 반영된다" 류.
커밋됐다면 **이후 권한 회수 로직이 깨져도 빨간불이 뜨지 않았다.**

## 왜 자동 게이트로 안 잡히나 (이 조항의 존재 이유)

**빌드도 테스트도 초록이었다.** 줄어든 테스트는 실패하지 않는다 —
컴파일 통과, 남은 7건 전부 통과, 컨벤션 lint 통과. 커버리지 소실은 **초록불 뒤에 숨는다.**

잡은 것은 커밋 전 **델타 재리뷰**였고, 그 방법은 `git show HEAD:<파일>` 로 원본과 대조한 것이었다.
즉 사람(또는 리뷰 에이전트)이 **의도적으로 대조하지 않으면 영영 안 걸린다.**

## 놓친 신호 — 도구 결과 문구

- 신규 생성: `File created successfully at <경로>`
- 기존 덮어쓰기: `The file <경로> has been updated successfully`

나는 **후자를 받고도** 신규 생성으로 읽었다. 이 문구 차이가 유일한 실시간 경보였다.

## 왜 테스트 파일이 특히 위험한가

같은 클래스에 **다른 관심사를 검증하는 케이스가 이미 살고 있을 확률이 높다.**
그 파일에는 프로브 노출 판정·메뉴 활성경로·인가 조회 1회 계약이 한데 있었고,
나는 새로 붙이려던 관심사 하나만 생각하고 파일 전체를 갈아엎었다.

⇒ 성격이 다른 검증을 추가할 땐 같은 파일을 재작성하지 말고 **별도 테스트 클래스로 분리**한다.
이번 해소도 별도 클래스 분리였다(원본 18건은 `git checkout HEAD --` 로 전량 복원,
실제 갱신이 필요한 것은 1건뿐이었다).

## 복원 절차

`git checkout HEAD -- <파일>` 이 인덱스·워킹트리를 함께 되돌린다.
단 그 파일에 **살려야 할 내 편집이 섞여 있으면 먼저 사본을 뜬 뒤** 복원한다
(HEAD 복원은 커밋 안 된 모든 편집을 함께 지운다 — 같은 축의 사고 선례가 있다).

## 파생 게이트

이 사고를 계기로 **staged diff 의 테스트 파일 `@Test` 증감 검사**를 훅으로 승격했다
(`test-count-guard.sh`). 선언만으로는 안 지켜지고, 위에 적었듯 빌드·테스트로는 안 잡히기 때문이다.


## 경위(2026-09-17 이동)

**편집안전:4 축약(원문 잔여):** "`git cat-file -e HEAD:<경로>`·`ls` 1콜로 부재 확인, 있으면 `Edit`. 도구 결과 `File created` = 신규 / `has been updated` = 덮어쓰기 — 신규인 줄 알았는데 updated 면 멈추고 `git show HEAD:<파일>` 로 원본 확인. **테스트 파일 특히 위험** — 성격이 다른 검증은 별도 테스트 클래스로. 커버리지 소실은 빌드·테스트가 초록이라 못 잡는다(staged diff 의 `@Test` 개수 증감을 본다)." → 존재 확인은 훅 `write-overwrite-guard.sh`(PreToolUse Write, deny, 우회 `ALLOW_WRITE_OVERWRITE=1`) 로 승격, 나머지 판정은 여기.

## 대형·복제 파일(편집안전:9·10 축약, 2026-09-17 이동)

**9(원문 잔여):** "판정은 diff 크기가 아니라 **파일 총 라인**이다(큰 파일일수록 리뷰 누락·복제 드리프트가 함께 자란다). 분해가 이번 범위를 넘으면 사유를 적고 진행하되 **사용자에게 말한다**(침묵 통과 금지)." → 알림은 훅 `large-file-split-reminder.sh`(PostToolUse Write|Edit, >1000줄 경고).

**10(원문 잔여):** "같은 파일이 두 모듈에 복제돼 있으면 한쪽만 고치지 마라 — **편집 전 양쪽을 실측**하고, 한쪽만 고칠 거면 그 판단을 명시한다. 레포별 대형·복제 파일 목록은 프로젝트 memory." → 짝 알림은 훅 `twin-file-reminder.sh`(형제 모듈 같은 상대경로). 경고형이라 동명이지만 의도적으로 다른 파일도 걸릴 수 있다(무해).
