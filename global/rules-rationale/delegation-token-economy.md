서브에이전트 1개 = 최소 ~40k 토큰. 위임/스킬 오버헤드가 작업 난이도로 정당화될 때만 쓴다.

**Why:** 2026-07-03 완료알림 규약을 형제 레포 7종 CLAUDE.md에 "불릿 한 줄" 삽입하는 데 레포당 풀 sonnet 에이전트를 팬아웃 → **~300k 토큰**(각 41~48k) 소모. 실제로는 `grep`+`Edit` 2콜/파일이면 되는 기계적 편집이라 인라인이면 ~40k, 단일 에이전트로 묶어도 ~50k. **6~8배 과소비.** 추가로 Stop 훅 한 줄 추가에 `update-config` 스킬을 호출해 settings 전체 JSON 스키마(마켓플레이스·샌드박스 등 무관 수백 줄)가 컨텍스트에 박힘 = 별도 낭비. 결과물은 정상이었으나 토큰 효율이 나빴고 사용자가 지적(/honest).

**How to apply:**
- 위임 전 자문: "내가 인라인으로 하면 몇 콜인가?" → 소수면 직접 한다.
- **동일·기계적 편집을 N개 대상에** = 팬아웃 금지. 인라인(`grep`+`Edit`) 직접, 대상 많으면 에이전트 **1개**로 일괄. 팬아웃은 대상마다 판단이 갈리는 무거운 작업(리뷰·조사·설계·검증)에만.
- **한 줄짜리 변경**(훅 추가·설정 한 줄)엔 무거운 스킬 호출 지양 → 파일 직접 Read+Edit. 스킬은 절차가 실제 복잡하거나 스키마 참조가 정말 필요할 때만.
- 정당했던 지출과 구분: "조용히 죽으면 모르는" 훅(알림 등)의 파이프 테스트·검증은 값어치 있음(과잉 아님).

정본 규칙 = 전역 `~/.claude/CLAUDE.md` "위임·도구 경제". 단계별 effort·모델 전환 사다리 = [[effort-model-operation]]. 관련 [[delegate-in-background]](백그라운드 위임은 위임이 정당할 때의 방식이지, 위임 여부 판단이 아님).
