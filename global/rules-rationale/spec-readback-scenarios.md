# 사양 되읽기 — 설계 결정을 Given/When/Then 시나리오로 컨펌받는 단계 (근거)

전역 규약 조항 "설계 결정은 시나리오로 되읽어 컨펌받은 뒤 박는다"의 근거·경위. (규칙 문장은 `~/.claude/CLAUDE.md`, 여긴 서사만.)

## 실측(2026-09-03, 예시 레포 소통방 1~3단계)
- 결함 적발 층: 다관점 리뷰 3회 CONFIRMED 23(HIGH 3) · 델타 재리뷰 BLOCK 1 + 수리가 만든 결함 2 · E2E(경합) 1 · **사용자 1**.
- 사용자만 잡은 결함 = "권역에 학교를 배정할 때 소통방이 생성되지 않는다". 설계서(D 목록)에는 "권역 생성 시 방 생성"만 있었고 코드는 **설계서와 정확히 일치**했다.
  → 리뷰(diff 의 결함을 찾는다)·단위테스트(설계서대로 동작하나)·E2E(화면이 설계서대로 보이나)가 **전부 같은 전제 위에서** 돌아 구조적 사각.
- 해석 오해의 형태 = **경계·경로 누락**: "방을 만든다"는 결정이 "어느 경로로 들어와도(생성·배정·해제·업데이트) 방이 있어야 한다"는 뜻이었는데, 결정 문장이 한 경로만 적었다.

## 왜 되읽기가 잡나
- Given/When/Then 으로 적으면 **When 이 경로**가 된다 — "When 권역에 학교를 배정하면 Then 그 권역의 방이 있다"를 쓰는 순간 "배정 경로도 포함"이 드러난다.
- 결정 하나당 1~3줄이라 비용이 작고, 컨펌은 사용자 몫(기계가 못 잡는 층을 사람에게 되돌리는 유일한 자리).
- 컨펌본을 설계서 "§시나리오(컨펌본)" 절에 두면 E2E 케이스 목록의 씨앗이 된다(경합 시나리오 5-3절과 같은 축).

## 적용 위치
- 전역 규약(방법론) + 프로젝트 `new-screen` 스킬 §0 체크리스트 2번 + 프로젝트 규약 "피그마 컨펌 먼저" 조항 꼬리.
- 발동 시점 = 사용자 결정 목록이 확정된 직후, 구현 착수 전. 화면 없는 백엔드 결정(상태전이·채번·인가)도 동일.
