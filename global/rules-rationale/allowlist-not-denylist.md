# 입력 방어는 금지 목록이 아니라 허용 목록으로

**조항(전역 §비동기·검증)**: 막을 것을 열거하는 수리는 변형이 계속 나온다. 허용할 형태를 정확히 적고 나머지는 기존 방어에 맡긴다. 금지 목록을 늘리는 수리가 2회째면 설계를 뒤집는다.

## 경위 (2026-09-07 예시 레포, `AppHtmlSanitizer`)

에디터 본문 이미지는 컨텍스트패스 없는 상대 경로(`/upload/...`)로 저장된다. 그런데 jsoup 은 프로토콜 화이트리스트를 **절대화한 값**으로 검사하므로 상대 `src` 는 절대화가 빈 값이 돼 **속성째 사라진다**(실측: `<img alt="포스터">`).

**1차 수리(틀린 접근)** — `preserveRelativeLinks(true)` + baseUri 로 상대링크를 통째로 허용. 이미지는 살아났지만 **사용자 입력의 모든 상대 URL 이 함께 통과**하게 됐다. 리뷰가 실측으로 잡음:

```
변경 전: <img>                                  ← 제거
변경 후: <img src="//evil.example/track.png">   ← 통과 (외부 비콘)
```

**2차 수리(같은 오류의 반복)** — 후처리로 `//` 시작과 `..` 포함 속성을 제거하는 **금지 목록**. 다음 라운드에서 우회 6종이 실측됐다:

```
href="\evil.example/p"          WHATWG: \ → /
href="/\evil.example/p"
src=" //evil.example/t.png"     선행 공백·탭·개행
src="/⏎/evil.example/t.png"     URL 내부 개행
src="/upload/%2e%2e/etc"        %2e 디코드
src="/upload/..\..\etc"
```

브라우저 URL 파서(WHATWG)는 특수 스킴에서 `\`→`/` 치환, 선행 C0/공백 제거, 위치 무관 tab/LF/CR 제거를 한다. **금지 목록이 브라우저 파서의 관용성을 따라잡을 수 없다.**

**3차(뒤집기)** — 상대링크 허용을 **끄고**(= 원래 방어력 복귀), 우리가 만든 경로만 정제 전후로 왕복 치환:

```
/upload/X  →  https://cms.invalid/upload/X  →  Jsoup.clean(원래 정책)  →  /upload/X
```

되살아나는 형태가 **한 가지로 고정**된다. 마크 패턴도 좁혔다 — `/upload/` 로 시작하면서 같은 속성값에 `..`·`%2e` 가 **없을 때만**. 조건 밖 값은 마크되지 않아 jsoup 의 원래 검사에 걸려 사라진다. 우회 6종 + `..` + `%2e` 전부 차단, 정상 경로·절대 URL 유지 — 테스트 9건으로 고정.

## 판정

- 방어를 위해 **"이런 건 막는다"** 목록을 쓰고 있는가 → 뒤집을 후보
- 그 목록에 항목을 **추가하는 수리가 2회째**인가 → 즉시 뒤집는다
- 뒤집는 법 = **되살릴/허용할 형태를 정확히 적고**, 나머지는 기존(더 엄격한) 기본 방어에 맡긴다

## 부수 효과

블랙리스트 후처리가 낳았던 부수 지적 3건(다른 URL 속성 `cite` 누락 / 쿼리스트링의 `../` 과대 매칭 / javadoc 이 코드를 반증)이 **접근을 뒤집자 통째로 사라졌다**. 금지 목록은 그 자체가 결함의 생성기다.
