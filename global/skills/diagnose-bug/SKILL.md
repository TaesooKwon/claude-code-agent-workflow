# diagnose-bug — 재현 루프 먼저, 가설은 그 다음

> 출처: mattpocock/skills `skills/engineering/diagnosing-bugs/SKILL.md` @5863806 (MIT) 개작.

**핵심은 1단계다.** 이 버그에서 빨개지는 빠르고 결정적인 판정 명령이 생기면 원인은 찾게 된다. 그 명령 없이 코드를 읽어 이론을 세우기 시작했다면 멈춘다 — 이 스킬이 막으려는 실패가 바로 그것이다.

명령·출력·캡처를 보여줄 때 비밀값(비밀번호·토큰·세션 쿠키·개인정보)은 `<REDACTED>` 로 가린다.

## 1단계: 판정 루프 만들기

수단(우리 스택):
- **실패 테스트** — `mvn test -pl <모듈> -am -Dtest=<클래스>#<메서드> -Dmaven.repo.local=<핀>` (핀·래퍼는 `harness` 스킬).
- **실행 중인 앱에 curl** — 병행 세션을 운용하면 앱은 한 세션(메인)만 띄운다. 앱 기동이 금지된 세션은 curl 루프가 필요하면 메인에 "기동 + 이 요청" 을 의뢰한다.
- **화면(JS 렌더·로그인 게이트)** — `playwright-verify` 스킬. 앱 기동이 금지된 세션이면 위와 같이 메인 의뢰.
- **회귀** — 되던 커밋과 깨진 커밋을 같은 입력으로 비교. 다른 커밋을 꺼낼 땐 레포 밖 worktree 에서(공유 워킹트리 checkout 금지 — [[parallel-session-shared-index]]).
- **간헐 버그** — 깨끗한 재현이 아니라 **재현율**을 올린다(반복·병렬·타이밍 창 좁히기). 1% 는 못 다루고 50% 는 다룬다.

루프를 조인다: 더 빠르게(범위 좁히기) · 더 날카롭게(증상 자체를 단언, "에러 안 남" 금지) · 더 결정적으로(시각·난수·데이터 고정).

루프를 도저히 못 만들면 멈추고, 시도한 수단을 나열한 뒤 사용자에게 재현 조건(계정·데이터·순서)이나 가린 로그를 요청한다. 루프 없이 가설로 넘어가지 않는다.

**완료 기준** — 명령 하나를 이름으로 댈 수 있고, 이미 1회 실행해 출력을 보였으며:
- [ ] 실제 버그 경로를 타고 **사용자가 말한 증상 그대로**를 단언한다(고쳐지면 초록이 된다)
- [ ] 돌릴 때마다 판정이 같다(간헐 버그는 고정된 높은 재현율)
- [ ] 초 단위로 끝난다
- [ ] 사람 손 없이 돈다

## 2단계: 재현 + 최소화

- 루프가 **사용자가 말한 그 증상**으로 빨개지는지 확인한다 — 근처의 다른 실패면 엉뚱한 수정이 된다.
- 입력·호출자·설정·데이터·단계를 하나씩 빼며 매번 다시 돌려, 남은 요소가 전부 "빼면 초록이 되는" 것만 남을 때까지 줄인다.

## 3단계: 가설

검증 전에 **순위 매긴 가설 3~5개**를 쓴다(하나만 세우면 첫 그럴듯한 생각에 고정된다). 각 가설은 예측문을 갖는다:

> "<X>가 원인이라면 <Y>를 바꾸면 버그가 사라지고 / <Z>를 바꾸면 악화된다."

예측문을 못 쓰면 가설이 아니다 — 버리거나 날카롭게 한다. 목록은 **진행 공유**로 사용자에게 보이되 결정을 요청하지 않는다. 답을 기다리지 않고 1순위부터 검증하고, 사용자가 순위를 바꾸면 따른다.

## 4단계: 계측

- 탐침 하나 = 3단계 예측 하나. **한 번에 변수 하나.**
- 디버거 > 가설을 가르는 경계의 표적 로그 > "전부 찍고 grep"(금지).
- **디버그 로그엔 고유 태그** `[DEBUG-xxxx]`(xxxx = 이번 진단의 임의 16진 4자, 예: `a4f2` — 커밋 훅 경고가 16진만 인식한다). 정리가 grep 한 번이 된다 — 태그 없는 로그는 살아남는다.
- 성능 회귀면 로그 대신 기준 측정(응답 시간·실행 계획)부터 잡고 좁힌다.

## 5단계: 수정 + 회귀 테스트

- 수정 **전에** 회귀 테스트를 쓴다 — 단 **올바른 seam**(버그가 실제로 일어나는 호출 패턴을 그대로 태우는 경계)이 있을 때만. 너무 얕은 seam(여러 호출자가 얽혀야 나는 버그를 단일 호출로 테스트)은 거짓 안심을 준다.
- **올바른 seam 이 없으면 그것이 발견이다** — 구조가 이 버그를 고정하지 못하게 막고 있다고 보고에 적는다.
- 빨간불 확인·기대값 출처는 전역 반증검사 조항을 따른다([[falsification-can-lie]]). 수정은 래더의 "공유 지점 근본 원인 1회".
- 수정 후 최소화 전 원래 시나리오로 1단계 루프를 다시 돌린다.

## 6단계: 정리 (완료 선언 전 필수)

- [ ] 원래 재현이 더는 안 된다(1단계 루프 재실행)
- [ ] 회귀 테스트 통과(`Tests run: N>0`) — 또는 seam 부재를 보고에 적음
- [ ] `[DEBUG-` 태그 grep 0건
- [ ] 임시 하네스·스크립트 삭제
- [ ] **맞았던 가설**을 커밋 메시지(또는 보고)에 적는다 — 다음 진단자가 배운다
