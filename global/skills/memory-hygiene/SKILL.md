# memory-hygiene — memory 정기 위생 스윕

**목적:** memory가 시간순 퇴적층이 되는 것을 막는다. stale 상태(완료됐는데 🔴 표시 잔존)를 후속 세션이 사실로 오독하는 사고를 정기 스윕으로 차단. (배경: 수동 스윕 3회 반복 → 승격사다리로 스킬화)

## 절차

### 1. 기계적 스캔 (스크립트)

```bash
bash ~/.claude/skills/memory-hygiene/scripts/scan.sh
```

현재 프로젝트의 memory 디렉터리를 자동 탐지해 리포트 출력: ①인덱스 죽은 링크 ②본문 죽은 `[[위키링크]]` ③진행표시 마커 잔존 위치(인덱스/description/본문) ④pending·next-* 파일 ⑤인덱스 비대 라인. **스캔은 후보 나열까지만 — 각 항목의 처분은 아래 판단 기준으로.**

### 2. 항목별 판단·처분

| 발견 | 판단 | 처분 |
|---|---|---|
| 진행표시(🔴/🟡/미검증/검증중/대기 등) | 본문·history와 대조해 실제로 완료됐나 | 완료면 **3곳 동기 치환**(본문·frontmatter description·MEMORY.md 인덱스 라인) — ✅만 덧붙이지 말고 구식 표시를 소거 |
| 같은 파일 내 상태 공존(미검증 vs 완료) | 최신 상태 확인 | 구식 스냅샷 소거, 최신만 남김 |
| 완료된 `next-*`/`*-pending` | 재사용 교훈이 남았나 | 교훈만 evergreen memory/`skills-*` 토픽에 병합 후 **파일 삭제**(서사는 history가 보존, 복구는 미러 git 이력) |
| 죽은 `[[링크]]` | 미래 마킹(의도)인가 오타/은퇴 잔재인가 | 잔재면 제거·정정, 의도면 유지 |

| 인덱스 비대 라인 | "열지 판단할 한 줄 훅"을 넘는가 | 본문 요약 인라인 제거, 훅만 남김 |
| `promotion-candidates` 항목 | 3회째 도달했나 | 도달 시 승격 검토, 처리(승격/폐기) 후 라인 제거 |
| 결정 기록(설계·선택 이유) | 남길 가치 = ①되돌리기 어렵다 ②맥락 없이 보면 의외다 ③실제 대안 사이에서 고른 결과다 — 셋 다인가 | 셋 다면 유지(evergreen), 하나라도 아니면 history 로 충분하니 병합·삭제 후보 |
| 날짜 없는 상태 주장("현재 ~", "~이다" 가 코드·설정 상태를 말함) | 언제 사실이었나 | 날짜(또는 커밋)를 붙인다. 상태가 바뀌었으면 옛 문장을 고쳐 쓰지 말고 새 날짜 문장을 추가하고 옛 것에 `(superseded YYYY-MM-DD)` 표시(진행표시 마커·상태 공존은 위 행들대로 치환·소거) |

### 2-1. 인계 큐는 복사 전에 재측정

**인계 큐(`*-pending`·`next-*`·MEMORY.md 인덱스)를 복사·보고하기 전에 값싼 항목(줄번호·경로·수치)은 재측정해 치환한다** — stale 라인은 그대로 복사되며 사실로 굳는다. 재측정 비용이 1~2콜을 넘으면 옮겨 적지 말고 "재측정 필요" 로 표시한다. 근거 = [[stale-carryover-queue]].

주의: 대상이 많고 **파일마다 독립 판단**이 필요하면 규약의 Workflow 선제안 대상(팬아웃 검토). 소수면 인라인.

### 3. 마무리 기록

- `MEMORY.md` 말미 "정리 이력(요약)" 라인 갱신(날짜+골자, 누적 나열 말고 압축).
- `docs/agent_history.md`(있으면)에 스윕 결과 한 항목(처분 건수·대표 사례).
- 다음 스윕을 위한 잔여·보류 항목은 해당 memory에 명시(새 pending 양산 금지).
