# client-questionnaire — 발주처 질의서

> 출처: mattpocock/skills `skills/productivity/to-questionnaire/SKILL.md` @5863806 (MIT) 개작.

**주제가 아니라 발송을 묻는다.** 주제를 모르기 때문에 질의서를 쓰는 것이니 주제로 사용자를 인터뷰하지 않는다. 사용자가 항상 답할 수 있는 두 가지만 묻고, 질의서의 질문은 "수신자가 아는 것"과 "우리가 필요한 것" 사이의 간극을 겨눈다.

1. **누구에게 보내나?** 한 번에 묻는다: 수신자의 소속·역할, 이 업무에 대한 전문성, 우리와의 관계(발주처 담당자·현업·타 업체). 어조와 맥락 분량이 여기서 정해진다. 완료 = 수신자가 누구이고 우리가 모르는 무엇을 아는지 말할 수 있다.
2. **무엇을 받아야 하나?** 한 번에 묻는다: 우리가 혼자 못 정하는 결정·사실 목록. 완료 = 답을 받은 뒤 할 수 있게 될 일의 구체 목록이 있다.
3. **작성.** 아래 구조로 쓰고 경로를 보고한다. 완료 = 파일이 있고 2단계 항목마다 겨누는 질문이 있다.

**수신자 1명 = 문서 1개.** 답이 여러 사람에게 흩어져 있으면 사람마다 따로 만든다.

## 저장 위치 — 쓰기 전 관문

기본 위치 = 해당 레포 `docs/questionnaire-<주제>.md`. 쓰기 전에 `git check-ignore -q <경로>` 로 git 격리를 확인한다:
- 통과 → 그 경로에 쓴다.
- 실패(추적 대상) → 사용자에게 `.git/info/exclude` 에 추가할지 묻는다. 거부하면 git 밖 경로(스크래치패드)에 쓰고 그 경로를 보고한다.

## 금지 내용 (외부 발송 문서)

내부 코드 경로·클래스명·테이블/컬럼명·서버 주소·계정, 개인정보(이름·연락처는 수신자 표기 외 금지), 내부 일정·비용 판단은 넣지 않는다. 기술 사실이 필요하면 화면·기능 이름과 업무 용어로 바꿔 쓴다.

## 문서 구조

한국어 공문 톤(경어체, "~하여 주시기 바랍니다"). 중요한 질문부터 — 비동기라 한 번만 읽힐 수 있다. 질문이 여럿이면 주제별 `##` 로 묶는다.

```markdown
# <질의서 제목>

**목적:** 이 질의서가 필요한 이유와 답에 걸린 결정
**발신:** <우리 측 담당> **수신:** <수신자> **회신 기한:** <날짜>
**답변 활용:** <답이 어디에 쓰이는지>

## 배경
우리 머릿속에 없던 수신자가 잘 답할 수 있을 만큼의 한 단락.

## 답변 방법
기한과 대략의 소요. 일부만 답하셔도, "모르겠다"고 하셔도 도움이 됩니다 — 확실하지 않은 항목은 건너뛰지 말고 표시하여 주시기 바랍니다.

## <주제>

### <질문 — 한 질문에 한 가지만, 복합 질문 금지>

_이 질문이 필요한 이유: <오해되거나 대충 답할 여지가 있을 때만 한 줄>_

> (답변)

## 기타
저희가 묻지 않았지만 알아야 할 사항이 있으면 적어 주시기 바랍니다.
```
