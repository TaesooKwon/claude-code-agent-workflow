# 전역 에이전트 지침

> **`[[포인터]]` 정본 = `~/.claude/rules-rationale/<이름>.md`**(자동 로드 아님). 전역 조항 근거를 프로젝트 memory 로 밀지 마라(회상은 프로젝트별). 다이어트 전 전문 = [[claude-global-archive-20260917]] · [[claude-global-archive-20260903]](조항 제목으로 찾는다).

## 착수 관문 (작업마다 첫 도구 호출 전)
- **사실이 담긴 선택지·설계는 반증 결과를 받은 뒤 낸다**(「상태주장」 절 3단계 ②).

## 규약 배치·전파
- **규약에 한 줄 쓰기 전에 "어디 몫인가"를 판정하라:** 전역·프로젝트 `CLAUDE.md`·`MEMORY.md` 는 매 세션 고정비. 경위·실측·사례·수치 → memory/rationale(규약엔 규칙 문장 + 포인터만). 한 항목 3줄 초과 = 밀어낼 후보. 축소는 사용자 승인 후(유실 실측 있음). [[session-token-cost-profile]]
- **배치 3규칙** = ①스택 불문 방법론 → 전역 단일정본(프로젝트엔 포인터 + 그 레포 판정축) ②동일 스택 공유 자산 규칙 → 각 프로젝트 md 에 중복 기재 ③도메인값·접속정보·포트 → 프로젝트 격리. 형제 레포 대조 절차·함정은 [[rule-propagation-crossrepo]].
- **정책을 개정하면 복제된 레이어를 grep 으로 훑어 잔존 0 을 실측한다.** 레이어 = ①프로젝트 md ②전역 ③`SKILL.md` ④훅·settings ⑤스캐폴드 ⑥이식 킷. 히트는 정책 서술인지 트리거 문구인지 확인(스킬 `description:` 은 존치). 인용 경로의 실재는 `agent-audit` 가 백틱 토큰을 대조한다(경고만).
- **지침 문구는 실패 형태에 맞춘다:** 알면서 어김 = 금지+증상 / 모양이 틀림 = 구성 레시피 / 항목 누락 = 템플릿 필수 칸 / 조건부 = 관측 가능한 조건문. 예외 조항으로 범위를 가두지 말고 구조를 바꾼다. 스킬 `description` 엔 단계 순서·횟수를 요약하지 않는다(에이전트가 본문 대신 요약을 따른다). [[guidance-form-matches-failure]]

## 위임·도구 경제
- **서브에이전트 1개 = 최소 ~40k 토큰.** 위임·스킬 오버헤드가 난이도로 정당화될 때만. 판단 = "인라인이면 몇 콜인가"가 소수면 위임이 손해. [[delegation-token-economy]]
- **동일·기계적 편집 N개 = 팬아웃 금지**(인라인 `grep`+`Edit`, 많으면 에이전트 1개 일괄). 팬아웃은 대상마다 판단이 갈리는 작업(리뷰·조사·설계·검증)만. 한 줄 변경에 무거운 스킬 호출 지양(파일 직접 Read+Edit).
- **커밋으로 한 덩어리가 종결되면 "다음 큰 작업은 새 세션 권장" 한 줄을 완료 보고에 붙이고, 무관 주제 전환엔 `/clear` 권유**(훅 승격 대기).
- **팬아웃 우선순위 = ①인라인 → ②Workflow(결과만 회수) → ③대화형 팀.** 한 건 위임 후 결과 회수 = background 서브에이전트이며 **`name:` 금지**(이름을 주면 팀메이트가 되어 보고가 유실된다). 상대 세션의 능력(`SendMessage` 보유·승인 정책)은 스폰 전 확인 — 목록·함정은 [[delegation-token-economy]].
- **위임·워크플로 프롬프트엔 하한선 5항목을 라벨째 전사**(①트러스트 경계 입력검증 ②데이터손실 방지 에러처리(경합 포함) ③보안(인가·시크릿·운영가드) ④접근성 ⑤명시요청 기능). 무의미하면 "N/A" 명시 — 침묵 누락 금지(훅 `delegation-floor-reminder.sh` 가 Agent·Workflow 호출 때 빠진 라벨을 경고 — 차단 아님). 코너컷은 `// ponytail:` 표기 지시. [[delegation-prompt-transcribe-floor]]

## 편집 안전
- **최소주의 래더(포니테일):** 문제를 끝까지 읽고 변경이 닿는 곳(호출처·테스트·XML/템플릿/JS 문자열 참조·설정)을 grep 으로 나열한 뒤 ①존재할 필요가 있나(YAGNI) → ②이 코드베이스에 이미 있나(재사용 — 프로젝트 공통이 네이티브보다 우선) → ③표준 라이브러리·플랫폼 네이티브·기존 의존성(몇 줄 때문에 의존성 추가 금지) → ④한눈에 읽히는 한 줄 → ⑤그제서야 최소 코드. 첫 성립 단에서 멈춘다. 구현 1개짜리 추상화·"나중용" 코드 금지, 추가보다 삭제, 최단 diff — 단 깨뜨린 호출처·테스트까지 완결하고, 버그 수정은 호출처를 다 본 뒤 공유 지점 근본 원인 1회. 하한선 5항목(①트러스트 경계 입력검증 ②데이터손실 방지 에러처리 ③보안 ④접근성 ⑤명시요청 기능)은 래더가 절대 못 자른다 — 옮기거나 합친 코드도 에러처리·검증을 그대로 가져간다. 자른 코너는 `// ponytail: <한계> / <업그레이드 경로>`. [[ponytail-ladder]]
- **쓰기 전에 신규인지 확인하라** — 존재하면 `Edit`(훅 `write-overwrite-guard.sh` 가 차단, 의도한 전면 재작성은 `ALLOW_WRITE_OVERWRITE=1`). 원격 반영 가드의 우회는 `ALLOW_GIT_PUSH=1`(사용자가 그것을 지시했을 때만). [[write-overwrites-existing-file]]
- **코드를 걷거나 더하면 그 코드를 서술하는 주석·문서도 같은 diff 에서 고친다**(판정 = "이 편집으로 거짓이 된 문장이 남는가"). 복제한 코드의 주석은 자리마다 다시 판정한다. [[comment-drift-same-edit-unit]]
- **주석·문서에 개수(`N곳`·`N개`·`~뿐`)·배타(`X만`·`유일한`)·코드 밖 사실(실행 순서·호출처 수·다른 파일 동작)을 쓰지 않는다** — 대신 ①불변식 ②모집단 조회 명령을 적고, 근거 명령을 못 치면 역할로 서술한다. [[comment-drift-same-edit-unit]]
- **1,000줄 초과 파일은 줄을 더하기 전에 분해를 먼저 검토한다**(훅 `large-file-split-reminder.sh` 가 알린다) — 분해를 미루면 사유를 사용자에게 말한다(침묵 통과 금지).
- **복제본이 있는 파일은 한쪽만 고치지 마라**(훅 `twin-file-reminder.sh` 가 짝을 알린다) — 한쪽만 고칠 거면 그 판단을 명시한다.

## 상태주장·일반화·전제
- **상태주장은 검증 후 서술:** 현재 상태 주장이 권고·편집의 근거가 되면 서술 전에 반증할 가장 싼 명령 1개를 친다. 못 치면 "미검증(가정)" 라벨. 발동 = ①현재 상태 ②≤1~2콜 확인 가능 ③권고가 그 위에 얹힘(셋 다). [[verify-state-claims-before-asserting]]
- **"남은 일" 목록은 각 인계 memory 의 description 상태로 분류한 뒤 낸다** — 색인의 "~전 필독"은 열 트리거이지 할 일이 아니다. [[stale-carryover-queue]]
- **grep 0건은 부재 증명이 아니다** — 분모(모집단)·양성 대조·exit code 를 먼저 본다(글롭·변수는 항상 인용). 출력 캡(`head`/`tail`)은 표시 정리 전용 — 셀 때는 `grep -c`·`wc -l` 로 다시 센다. 부재 주장은 Read·LSP 로 교차. [[population-boundary-before-exhaustive-claim]]
- **수치·"전수"·"X만"을 쓸 땐 표본 수와 경계를 함께 적는다.** 표본 1로 규칙을 만들지 않는다. [[sample-size-and-premise-errors]]
- **팬아웃 전에 계약(전제)을 에이전트 1개로 먼저 검증받아라** — 틀린 전제는 실행자와 검증자가 함께 밟아 사후 리뷰로 못 잡는다. 리뷰/verify 계약의 첫 항목 = "전제 반증". [[sample-size-and-premise-errors]]
- **컨펌받을 설계·시나리오는 내기 전에 3단계(작업 형태 무관 — 단일 세션·병행 세션·서브에이전트 전부):** ①사실 문장마다 출처 태그 `[실측 파일:라인]`·`[조사]`·`[인계]`·`[가정]`(인계 memory 문장도 사실 주장) ②태그 붙은 전문을 설계를 쓰지 않은 검증자 1개(유휴 피어 세션, 없으면 background 서브에이전트)에 반증받아 머리에 "확인 n / 반증 m" — 태그는 자기 적용이라 혼자선 못 잡는다 — 인증·인가·경합 자원·데이터 삭제/이관 설계면 공격·실패 시나리오만 찾는 결함 사냥꾼 1개를 병행([[defect-hunter-standing]]) ③`[인계]`·`[가정]`이 남으면 제시하지 않는다. 반증은 도구가 아니라 단계다 — 사실이 담긴 선택지(AskUserQuestion)도 같은 관문이고, 검증자 경로가 막히면 다른 경로로 폴백할 뿐 생략하지 않는다. 이미 제시한 설계를 고치면 "바뀐 것 / 원인(사실 오류·누락·개선) / 출처" 표를 붙인다. [[sample-size-and-premise-errors]]
- **같은 실수가 2~3회 이어지면 개별 수리를 멈추고 생성기를 찾아 규약·훅으로 승격**, 진단을 보고 후 승인받는다. 방어하지 않는다. [[mistake-generator-promotion]]

## 비동기·검증
- **비동기 요청은 재진입 가드**(성공·실패 양쪽 해제) — 제출·생성·삭제 = 드롭 / 조회성 재렌더 = last-wins(시퀀스 토큰). 정적검사·단위테스트가 못 본다. [[inflight-guard-drop-vs-lastwins]]
- **공통 래퍼의 실패 계약은 착수 전 실물로 판정한다** — ⓐ실패 sentinel 을 콜백에 넘김(→ 성공 콜백 선두 가드) ⓑ실패 시 콜백 미호출(→ 잠금 해제는 콜백 밖) ⓒ래퍼 없음. 계약은 레이어(FO/BO)마다 다르고 팀 커밋 한 방에 바뀐다. ⓐ형 가드의 자동 검사는 레포 옵트인(마커 `.claude/conventions.enabled` 를 둔 레포에서만 harness 룰 M 이 경고) — 마커가 없으면 사람이 판정한다. [[async-wrapper-contract]]
- **다층 관통 기능은 코드 전에 얇은 실물 왕복 1회부터(워킹 스켈레톤):** 프로세스·파일 3개 이상을 관통하면 가장 얇은 경로 하나를 끝까지 실행해 통과시킨 뒤 살을 붙인다(목·lint·컴파일이 원리적으로 못 보는 조합). [[walking-skeleton-before-layers]]
- **첫 화면 전(인계 초기소스·팀 공통 모듈 유입 직후 포함) `foundation-check` 스킬로 기반 결정을 판정하고, 결함은 화면이 아니라 기반에서 고친다.** [[foundation-check]]
- **입력 방어는 금지 목록이 아니라 허용 목록으로 쓴다** — 금지 목록을 늘리는 수리가 2회째면 설계를 뒤집는다(발산 신호). [[allowlist-not-denylist]]
- **로직엔 단위테스트 기본:** 분기·계산·필터·상태전이·배선. 제외 = 단순 위임/CRUD 패스스루, 외부의존 경계(DB·네트워크·파일·렌더 → 통합/E2E). 도구는 프로젝트 규약이 지정.
- **경합 자원(폴링·동시 저장·상태전이·채번·커서)은 두 컨텍스트 동시 조작 E2E 가 필수** — 리뷰·단위테스트는 단일 흐름만 본다(절차 = `playwright-verify` 5-3절).
- **검증의 무게는 diff 의 크기가 아니라 성격에 비례** — A티어(워크플로 리뷰) = 실행 의미가 바뀌는 변경(판정축 ①로직 소스 ②쿼리·매퍼 ③인라인 스크립트 동작 ④조건·반복 바인딩 신설 중 하나라도 → A) / B티어(셀프리뷰) = 표현만. 커밋 전 훅 `commit-tier-calc.sh` 가 staged diff 로 계산해 보여주지만(소형 A 조건 포함), 훅 출력이 없는 환경에선 위 4축으로 직접 판정한다. 확장자·경로 축은 프로젝트 규약. [[review-alite-dedup]]
- **애매하면 A · B 로 내렸으면 사용자에게 말한다**(침묵 강등 금지). B 도 빌드·렌더 검증과 마커·지문 대조는 그대로.
- **리뷰 병합·게이트 계약 정본 = `.claude/workflows/commit-review.js`**(미판정은 기각이 아니라 게이트 차단) · 리뷰 위임 모델 하향·델타 재리뷰 생략 금지.
- **수리 → `git add` → 델타 재리뷰 → 빌드·검증 → 마커 → 커밋**(훅이 지문으로 강제). 델타 재리뷰 템플릿 = `.claude/workflows/delta-review.md`.
- **병행 세션과 인덱스를 공유할 땐 일괄 스테이징 금지**(`git add -A/--all/-u/.`·`commit -a`) — 리뷰는 worktree 에서 선실행(`args.repo`) → 상대 커밋 후 메인 재스테이징 → `git diff --cached | grep -v '^@@'` 대조 → 마커 → 커밋. 이 순서가 절차 정본이고, `.claude/scripts/wt-prereview.sh` 는 그 스크립트를 둔 레포에서만 쓴다(없으면 수기). [[parallel-session-shared-index]]
- **전체 E2E 회귀 스위트 = 온디맨드(커밋 게이트 금지):** 커밋 상비 게이트 = 빌드·단위테스트·자체 리뷰까지. 무거운 축(설정·인증/세션·DB 스키마·공통 모듈) 커밋 땐 전량 회귀를 제안(훅 승격 대기).
- **검증할 데이터가 없으면 만들어서 확인한다 — "데이터 없어 확인 불가"로 끝내지 않는다.** 대상 = 개발·로컬 DB(운영 금지). 화면 경유 생성 우선, 기존 테스트 행 임시 변경은 원값 기록 → 확인 → 원복(SELECT 대조). 계정 생성 경로·좌석 쓰기 권한 같은 레포별 예외는 프로젝트 규약. [[verify-create-test-data]]
- **테스트는 "통과"가 아니라 "실패할 수 있음"을 확인하라(반증검사):** 새·수정 단언은 기대값을 고의로 어긋나게 해 빨간불 1회 확인. 방어적 `if(있으면 확인) else 로그` 는 영원히 통과. ①셀렉터·경로는 실물 확정 ②응답 계약(메서드·status·코드)까지 단언 ③저장값 재조회 ④필터는 양성+음성 ⑤정리는 teardown 훅에.
- **반증검사 자체가 거짓을 말한다** — 몇 건이 왜 깨져야 하는지 먼저 적고 대조 · `Tests run: N>0`(미실행 ≠ 통과). [[falsification-can-lie]]
- **결함이 특정 층에만 살면 검증도 그 층에서**: 목 테스트는 아래 층(매퍼 SQL 텍스트·ORM 쿼리·생성 산출물)을 원리적으로 못 본다 → 렌더된 SQL 문자열을 단언. lint 는 문법을 볼 뿐 값의 자리는 안 본다.
